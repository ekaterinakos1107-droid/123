# Pinterest: раздача фото по 9 аккаунтам сериями

Конвейер, который раскидывает фото по 9 аккаунтам Pinterest **сериями** и
гарантирует, что **одно фото публикуется ровно один раз** — на всех сериях и
всех аккаунтах сразу.

## Идея «серии»

Серия = один заход публикаций. Ты кидаешь пачку фото (например, 9 штук — по
одному на аккаунт), скрипт раскидывает их по аккаунтам и фиксирует в реестре.
Позже приходит следующая серия — и так далее. Повторов между сериями быть не
может: каждое фото запоминается по «отпечатку» (хэшу).

## Как пользоваться

1. **Заведи серию.** Создай папку и закинь туда фото:
   ```
   photos/series/series-01/   ← фото для первой серии
   photos/series/series-02/   ← для второй
   ```
   Можно класть сколько угодно фото. 9 фото → по одному на каждый аккаунт.
   18 фото → по два. Если число не делится на 9 — лишние раздаются по кругу.

2. **Запусти распределение:**
   ```bash
   python3 distribute.py series-01            # разложить серию
   python3 distribute.py series-01 --dry-run  # сначала посмотреть план, ничего не трогая
   ```

3. **Забери план.** Появится `plans/series-01.csv`:
   ```
   series, account, filename, published_path
   ```
   Это и есть «какое фото → на какой аккаунт». По нему грузишь в postmypost.

## Что гарантирует уникальность

- Каждое фото получает **SHA-256 хэш** по содержимому — повтор ловится, даже
  если файл переименован.
- Использованные хэши хранятся в `ledger.csv` (реестр). Перед раздачей скрипт
  сверяется с ним: уже использованное фото **пропускается**.
- После раздачи фото **физически переезжает** в `photos/published/<серия>/<аккаунт>/` —
  из общего пула оно уходит и повторно не попадётся.

## Файлы

| Файл / папка | Назначение |
|---|---|
| `accounts.txt` | Список 9 аккаунтов (по строке). Замени на свои названия. |
| `photos/series/series-NN/` | Входящие фото серии (кладёшь сюда). |
| `photos/published/series-NN/<аккаунт>/` | Куда уезжают розданные фото. |
| `plans/series-NN.csv` | План публикации серии (для postmypost). |
| `ledger.csv` | Реестр всех использованных фото. **Не удаляй** — это память системы. |
| `distribute.py` | Скрипт распределения. |

## Распределение по кругу (round-robin)

Сейчас фото раздаются по очереди: 1-е фото → account-1, 2-е → account-2, …,
9-е → account-9, 10-е снова → account-1. Нагрузка равномерная.

Если захочешь другую логику (у каждого аккаунта своя тема/рубрика, или
случайно) — это меняется в `distribute.py` в пару строк.

## Что дальше (публикация в postmypost)

Два пути:
- **Ручной (старт):** берёшь `plans/series-NN.csv` и пакетно грузишь фото в
  postmypost по аккаунтам, ставишь расписание.
- **Автомат по MCP (рекомендуется):** у postmypost есть официальный MCP-сервер.
  После подключения публикация серии идёт автоматически — загрузка фото,
  создание пинов на нужные аккаунты, постановка в расписание. Инструкция:
  [CONNECT-POSTMYPOST.md](CONNECT-POSTMYPOST.md).
